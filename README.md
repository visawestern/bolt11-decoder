# bolt11 — локальный декодер Lightning-инвойсов (BOLT11)

Всё работает **локально в браузере**, без библиотек и CDN. Bech32 декодируется
своим кодом в `index.html` (BIP-173: `hrpExpand` / `polymod` / проверка checksum `== 1`).

## Открыть

```sh
cd bolt11
python3 -m http.server 8097
# http://localhost:8097/index.html  -> 200
```

Или просто открыть `index.html` двойным кликом (fetch не нужен, всё инлайн).

## Что разбирает

Вставка инвойса → разбор:

- `prefix`: `lnbc` / `lntb` / `lntbs` / `lnbcrt` (+ сеть)
- `сумма`: число + множитель `m`/`u`/`n`/`p` → BTC / sats / msats (через `BigInt`;
  `p` требует trailing `0`, иначе честная ошибка)
- `timestamp`: 35 бит → секунды + ISO-дата
- `p`: `payment_hash` (52 группы → 32 байта hex)
- `s`: `payment_secret` (52 группы → 32 байта hex)
- `d` / `h`: описание UTF-8 **или** `description_hash` hex (ровно одно из них)
- `x`: `expiry`, сек (по умолчанию `3600`)
- `c`: `min_final_cltv_expiry` (по умолчанию `18`)
- `n`: `payee`-pubkey (33 байта hex), если поля нет — честно пишется,
  что нужен secp256k1-recovery и ключ не показывается
- `f`: количество fallback-адресов
- `r`: количество `r`-полей + оценка числа хопов (`floor(bits/408)`)
- `9`: features hex, `m`: metadata hex
- `signature present`: да (104 группы → 65 байт: 64 `R||S` + 1 recovery),
  hex preview `R||S` + байт recovery

Поддерживает префикс `lightning:`, верхний/нижний регистр (смешанный — ошибка),
лимит 90 символов **не** применяется (по BOLT11 reader MUST без лимита).

## Честные ошибки (на мусор)

Пустой ввод, мусор, смешанный регистр, нет `1`-разделителя, символ вне
bech32-алфавита, неверная контрольная сумма, неверный префикс, ведущие нули /
нулевая сумма / `p` без trailing `0`, обрезанный `data`, обрезанное tagged-поле,
нет ровно одного `p`, неверная длина `p`/`h`/`s`/`n`, нет/оба `d`/`h`,
невалидный UTF-8 в `d`. Криптопроверка подписи **не** делается — так и написано
в UI (только факт наличия).

## Ограничения (честно)

- Нет secp256k1: payee только из `n`-поля; recovery не вычисляется.
- Нет проверки ECDSA-подписи (нужна криптография + hash preimage).
- `r`/`f`/`9`/`m` разбираются на уровне подсчёта/hex, без полного
  семантического валидатора BOLT7-channel-update.
